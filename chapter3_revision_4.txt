ITEM 2  (typo / formula formatting)
LOCATION: Chapter 3 > Model Evaluation Approach > Core Evaluation Metrics >
          paragraph beginning "The initial model assessment is based primarily on
          the F1 Score and IoU..."
--------------------------------------------------------------------------------
ISSUE A (formatting): the inline formula renders as "(F1 = 2 IOU/ (1 + IOU)) and
  herefore carry the same ranking information" — malformed symbol, inconsistent
  "IOU" casing, and "herefore".
ISSUE B (substance): the equation F1 = 2 x IoU / (1 + IoU) is CORRECT and is the
  standard Dice-Jaccard identity (F1 = Dice, IoU = Jaccard), but it is exact only
  PER IMAGE (same TP/FP/FN). The values you report are macro (per-image) AVERAGES,
  and averaging breaks the identity: mean(F1) is not 2*mean(IoU)/(1+mean(IoU)).
  Plugging your reported mean IoU into the formula gives ~0.607 / 0.492 / 0.454 /
  0.460 for CLRerNet / YOLOPX / HybridNets / SCNN, whereas your reported mean F1 is
  0.5564 / 0.4663 / 0.4275 / 0.4035 (the formula over-predicts, by Jensen's
  inequality). A reviewer who checks the formula against your means will see a
  mismatch.
ACTION (pick one):
  Option A - keep the formula but scope it to per-image and add a one-clause
    caveat (equation in $$ LaTeX for Word):
      "For a given image, F1 and IoU computed from the same pixels are
      monotonically related,
      $$F1 = \frac{2\,IoU}{1 + IoU}, \qquad IoU = \frac{F1}{2 - F1},$$
      and therefore carry the same ranking information; they are reported together
      for comparability with prior work rather than as independent confirmations.
      The dataset-level values reported here are per-image averages and so satisfy
      this relation only approximately."
  Option B - drop the explicit equation:
      "F1 and IoU computed from the same masks are monotonically related and carry
      largely the same ranking information; they are reported together for
      comparability with prior work but are not independent confirmations of one
      another."
  Either way also fix the "herefore" -> "therefore" and use "IoU" casing.
RATIONALE: the equation is mathematically and conventionally correct, but stated
  unqualified next to macro-averaged means it invites a false "the numbers don't
  satisfy your own formula" objection. Option A keeps the rigor and pre-empts that;
  Option B is simpler. The substantive point (F1/IoU are redundant; lean on
  precision/recall) holds under both.

ITEM 3  (missing methodology — carried over C-2)
LOCATION: Chapter 3 > Model Evaluation Approach > Evaluation Subset and Output
          Standardization > paragraph beginning "Because the datasets differ in
          image format, annotation structure..."
--------------------------------------------------------------------------------
ISSUE: Later results prose says CLRerNet's scores depend on "the rasterization
  width and tolerance defined in the evaluation methodology," but the methodology
  never defines them. (Your earlier GB40 comment flagged the same gap.)

ACTUAL VALUES FROM YOUR CODE (run_clrernet.sh):
   - W = MASK_THICKNESS = 16 px  (width used to rasterize CLRerNet polylines)
   - T = MASK_TOLERANCE = 8 px   (symmetric dilation of BOTH pred and GT masks)
   Confirmed: CLRerNet summary JSONs record tolerance_px = 8; the figure/table run
   uses these defaults. There is no separate "H" parameter (1640x590 is CLRerNet's
   internal inference letterbox, not a mask setting).

CRITICAL - the tolerance was applied to CLRerNet ONLY:
   - YOLOPX  summary JSON: tolerance_px = None (threshold = argmax) -> NO tolerance
   - HybridNets summary JSON: tolerance_px = None                   -> NO tolerance
   - SCNN: scored by a separate pixel-count eval                    -> NO tolerance
   Corroboration: on the SAME CULane GT, CLRerNet mean gt_px ~ 61,000 vs
   YOLOPX/HybridNets ~ 31,000 (CLRerNet's reference was fattened by T=8; theirs was
   not). Because dilating both pred and GT raises IoU/F1/recall, this asymmetry
   INFLATES CLRerNet relative to the mask models and directly affects the headline
   claim that CLRerNet has the highest IoU/F1. Do NOT write "applied identically to
   all four models" - that is currently false.

ACTION - pick one:
  OPTION 1 (recommended) - make it actually uniform, then the clean sentence is
    true. Re-score YOLOPX/HybridNets/SCNN through the same
    eval_segmentation_manifest --tolerance-px 8 path (it dilates both pred and GT),
    regenerate Table 12/13 + the figures, and verify whether CLRerNet still leads.
    Then append to the "Because the datasets differ..." paragraph:
      "Because lane-line detectors such as CLRerNet output structured polylines
      rather than dense masks, each model's lane output is first rendered to a
      binary lane mask at a fixed stroke width of 16 px. For all models, a
      stroke-width tolerance of 8 px is then applied symmetrically to both the
      predicted and reference masks before pixel-level true positives, false
      positives, and false negatives are counted, so thin-line and dense-mask
      outputs are compared on geometric agreement within 8 px rather than on raster
      width. Even so, a thin-line detector may score somewhat lower on pixel IoU/F1
      than a dense-mask model, which is why per-dataset precision and recall are
      also reported."

  OPTION 2 - if you do NOT re-score, describe the asymmetry honestly instead:
      "CLRerNet outputs structured polylines, which are rendered to a binary lane
      mask at a 16 px stroke width and scored with an 8 px stroke-width tolerance
      applied symmetrically to the predicted and reference masks. The mask-based
      models (YOLOPX, HybridNets, SCNN) are scored on their native output masks
      without this tolerance. Because the tolerance relaxes the matching, CLRerNet's
      pixel IoU/F1 are not directly comparable to the mask-based models and should
      be read together with the per-dataset precision and recall."
    NOTE: Option 2 weakens (and arguably invalidates) the "CLRerNet highest IoU/F1"
    conclusion, so Option 1 is strongly preferred.

RATIONALE: a reviewer's first question is whether the tolerance was applied to
  every model; right now it was not. Either equalize it (Option 1) or disclose it
  (Option 2) - but the comparison cannot be presented as uniform when it is not.

ITEM 10  (define every reported metric/value with a formula)
LOCATIONS: Chapter 3 > Model Evaluation Approach (Core Evaluation Metrics +
           Aggregation and Selection Considerations) and Preliminary Model
           Comparison (the cross-dataset consistency paragraph).
--------------------------------------------------------------------------------
DEFINITION AUDIT (what is vs is not currently defined):
  DEFINED (keep as is):
   - TP, FP, FN: stated under Table 11 ("true/false positives, false negatives,"
     defined at the pixel level). Good.
   - IoU, F1, Precision, Recall: given as formulas in Table 11. Good. If you want
     them as real equations rather than table text, the LaTeX is:
       $$IoU = \frac{TP}{TP + FP + FN}$$
       $$F1 = \frac{2\,TP}{2\,TP + FP + FN}$$
       $$Precision = \frac{TP}{TP + FP}$$
       $$Recall = \frac{TP}{TP + FN}$$
  NOT DEFINED (add formulas):
   - "dataset-normalized" mean, "per-dataset primary score," "coefficient of
     variation," and "cross-dataset consistency" are all used and reported as
     numbers but only described in words. Add the equations below.

ADD 1 - to "Aggregation and Selection Considerations," in/after the paragraph
  beginning "To avoid selecting a model that performs well only on one dataset...":
     "For each metric m (IoU, F1, Precision, or Recall), the dataset-level value is
     the per-image (macro) average over the N_d images in dataset d, and the
     overall dataset-normalized value is the unweighted mean of the four dataset-
     level values, so each dataset contributes equally regardless of its image
     count:
     $$m_d = \frac{1}{N_d}\sum_{i=1}^{N_d} m_{d,i}, \qquad
       \bar{m} = \frac{1}{D}\sum_{d=1}^{D} m_d,$$
     where D = 4 datasets."
  WHY: defines both "per-image average" and "dataset-normalized," and makes
  explicit that the normalization is an equal weight per dataset (the stated point
  that one dataset must not dominate).

ADD 2 - in the "Cross-dataset consistency is rated based on..." paragraph, replace
  the verbal definition with the explicit formulas:
     "For each dataset d, a primary score is the average of that dataset's F1 and
     IoU:
     $$S_d = \frac{F1_d + IoU_d}{2}.$$
     Cross-dataset consistency is one minus the coefficient of variation of the
     primary score across the four datasets:
     $$\text{Consistency} = 1 - \frac{\sigma_S}{\mu_S}, \qquad
       \mu_S = \frac{1}{D}\sum_{d=1}^{D} S_d, \qquad
       \sigma_S = \sqrt{\frac{1}{D}\sum_{d=1}^{D}\left(S_d - \mu_S\right)^2},$$
     with D = 4. Higher values indicate more stable performance across datasets;
     lower values indicate greater variation."
  NOTE: sigma here is the POPULATION standard deviation (divide by D, not D-1) -
  that is what reproduces the reported values (CLRerNet 0.6900, YOLOPX 0.6657,
  HybridNets 0.6347, SCNN 0.3730). If you used the sample std (D-1) anywhere, state
  that instead, but keep it consistent with the printed numbers.
  WHY: the consistency column is the one non-obvious computed value in Table 13;
  without the formula it is not reproducible, and "coefficient of variation" should
  be defined where first used.

RATIONALE: every number a reader sees in Chapter 3 should trace to a stated
  definition. After this, all four core metrics, the per-image and dataset-
  normalized means, the primary score, the coefficient of variation, and the
  consistency value are each defined by an equation.
